                                                        NeoConnect -- Hackathon

                                                                                Individual  4 Hours  Full Stack Challenge

1. Overview

You have 4 hours to build NeoConnect -- a staff feedback and complaint management
platform. The system gives employees a safe place to raise issues, vote on polls, and see how
management is responding. It should feel transparent, accountable, and easy to use.

Format         Individual
Time Limit     4 hours -- strict; late submissions will not be evaluated
Deliverable    Working app with source code pushed to the provided repository

Here is what the system needs to solve:

    · Every complaint gets a unique tracking ID and is assigned to a Case Manager --
         nothing gets lost

    · If a Case Manager does not respond within 7 working days, the system escalates
         automatically

    · A public hub shows how staff feedback has led to real changes in the company
    · The system flags departments with recurring issues so management can act early

3. Case Lifecycle

Every submission goes through a defined set of stages. This makes it easy to track progress
and spot delays.

Status       What It Means
New          Submission just came in, not yet reviewed
Assigned     Secretariat has assigned it to a Case Manager
In Progress  Case Manager is actively working on it
Pending      Waiting on more information from the staff member
Resolved     Case has been addressed and closed
Escalated    7-day rule triggered -- no response from Case Manager, Management has
             been alerted

4. Features to Build

4.1 Submission Form (Staff)
    · A form for staff to submit feedback or complaints
    · Fields: Category (Safety, Policy, Facilities, HR, Other), Department, Location, Severity
         (Low / Medium / High)
    · Option to submit anonymously -- a simple toggle that hides the submitter's name
    · File upload -- allow attaching a photo or PDF
    · Every submission must get a unique tracking ID in the format NEO-YYYY-001

4.2 Case Management (Secretariat & Case Manager)
    · Secretariat sees all incoming cases in an inbox view
    · Secretariat can assign a case to a Case Manager
    · Case Manager sees all cases assigned to them
    · Case Manager can update the status, add notes, and close the case
    · 7-day rule: if a Case Manager has not responded within 7 working days, send them a
         reminder and escalate to Management

4.3 Public Hub (Visible to All Staff)
    · Quarterly Digest -- a simple blog-style page showing summaries of resolved cases
    · Impact Tracking -- a table showing: what was raised  what action was taken  what
         changed
    · Minutes Archive -- a searchable list of uploaded meeting documents (PDFs)
4.4 Polling System
    · Secretariat can create polls with a question and multiple options
    · Staff can vote once per poll
    · Results are shown as a simple chart after voting

4.5 Analytics Dashboard (Secretariat & Admin)
    · A heatmap or bar chart showing which departments have the most open cases
    · Case counts broken down by status, category, and department
    · Hotspot flagging -- if 5 or more cases from the same department share the same
         category, highlight it

Use JWT-based authentication. Users must stay logged in after a page refresh. Each API route
must check the user's role before allowing access.

6. Rules

    · Write all your code during the 4-hour session.
    · Stick to the tech stack in Section 5. Ask first if you want to use something different.
    · You can use extra libraries for specific things like charts or date pickers, but they should

         not replace shadcn/ui.
    · Your app must run locally. Write clear setup instructions in your README.
    · Put all environment variables (MongoDB URI, JWT secret, etc.) in a .env.example file --

         do not hardcode them.
    · An organiser may ask you to walk through your code to confirm you wrote it yourself.
